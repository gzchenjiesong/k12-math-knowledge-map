### PRM-009: 内容保真与人工复核（最高优先）

**为什么**：内容是项目命门，错误讲解的危害大于缺失（`SPEC-008`）。R2 全量扫描已查出 3 处真实错误，证明风险不是理论上的。

**给模型的硬指令**
- 生成 / 改写任何讲解后，复核状态一律 `pending`，**绝不写 `verified`**（不自证红线 `SPEC-008`）。
- 写定理必带适用条件（费马 p∤a、欧拉互素、基本不等式各项为正、韦达验 Δ）；写"求 X"题必给明确结论。
- 改内容后必须跑 `node tests/verify_content.js` 并补针对性回归断言（`RUL-009`），否则视为没改完。
- 不得用"AI 再自查一遍"充当内容正确性保证；同源模型共享盲点。

**给用户/老师的人工复核清单（VFY-004，尚未签核）**
1. 对照孩子集训队讲义或权威教材，抽检 ≥ 10 个知识点。
2. 逐条看：定理条件齐不齐、例题数值对不对、问"求 X"有没有结论、口吻有没有把方法论说成硬定理。
3. 核对通过的知识点，在 `content_meta.js` 把 review 改为 `verified` 并记录核对人 + 日期，才算真正核实。
4. APP 内点"标记存疑"的节点，优先复核；发现错误按 `RUL-009` 五步闭环。

**如实口径**：本机制显著降低错误率，但**不保证零错误**；APP 是辅助讲解，不是教科书替代品，最终以学校讲义为准。
