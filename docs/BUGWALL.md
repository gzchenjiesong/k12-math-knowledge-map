## 一、已修复缺陷（不可回退）

### BUG-001: 小程序 scaffold 模板哈希校验全部失败

- **现象**：`workbuddy_miniprogram_scaffold` 报模板哈希校验失败，9 个文件全部不匹配。
- **根因**：manifest 按 LF 计算哈希，模板文件在 Windows 安装时被转成 CRLF。
- **修法**：备份官方模板到工作区 → 手动展开 → 换行符规范化为 LF → 逐文件校验哈希，9/9 与官方清单一致，产出与工具展开等价。
- **不可回退**：Program Files 只读，无法修复安装包；不要重新依赖 scaffold 工具，也不要把文件改回 CRLF。
- **防线**：`TST-012` 模板哈希基准比对。

### BUG-002: 定位器箭头函数语法笔误

- **现象**：HTML 图谱定位器 `filter(([,v])==>v>0)` 写成了 `==>`。
- **根因**：手写笔误。
- **修法**：改为 `=>`。
- **防线**：`TST-002` 内嵌脚本语法校验（new Function 解析）。

### BUG-003: 知识节点引用改名后漏改（5 处）

- **现象**：5 处引用了不存在的节点 ID（`j_pyth`、`j_rec`、`s_circle`、`o_num`、`o_seq`）。
- **根因**：编写时节点改名后未同步引用。
- **修法**：逐一改正为实际 ID。
- **防线**：`TST-008` 遍历 `pre` / `rel` / 题型 `nodes` 检查悬空引用，必须为 0。系统性排查同类：所有跨文件 ID 引用都纳入扫描。

### BUG-004: A3 挂图打印溢出成多页

- **现象**：挂图打印生成 3 页（应为单页 A3 横向）。
- **根因**：`.poster` 用 `min-height:281mm` + `padding`，叠加内容实际撑高溢出；`zoom:.72` 仅屏幕生效。
- **修法**：改 `height` 约束 + `@page` 边距归零由 poster 自控留白；压缩知识点行高 5.6mm → 5.0mm、模块间距 2.6mm → 2mm；留 2mm 余量规避 Chrome 舍入误差。
- **诊断陷阱**：`grep -c "/Type /Page"` 会把页面树根 `/Type /Pages` 也算进去，误报 2 页；正确判据是 `/Type /Page[^s]` 对象数 + MediaBox 尺寸（1191×843pt）。
- **防线**：`VFY-002` PDF 页数 = 1、MediaBox 为 A3 横向。

### BUG-005: WXML 标签不匹配与长按事件重复绑定

- **现象**：`cards.wxml` 出现 `</text>` 误闭合；`graph.wxml` 同一节点同时写 `bindtap` 与 `bindlongpress` 指向 `goNode`，长按无法独立切状态。
- **根因**：手写标签疏漏；交互未拆分。
- **修法**：修正闭合标签；拆成 `bindtap="goNode"` + `bindlongpress="cycleStatus"` 两个动作。
- **防线**：`TST-004` WXML 标签栈配对；`TST-010` 交互逻辑模拟。

### BUG-006: 图谱初始渲染三大来源全折叠

- **现象**：打开页面只见三个标题，用户不知道要展开。
- **根因**：初始 `closed` 类默认加在所有来源上。
- **修法**：无搜索时默认展开第一个来源，有搜索时全部展开（避免搜索结果被折叠隐藏）。曾有一次改法导致搜索结果被藏，已修正为该条件分支。
- **防线**：`TST-010` 默认展开断言 + 搜索全展开断言。

### BUG-007: TOPICS_BY_NODE 结构误用

- **现象**：授课页 `lesson.js` 把 `TOPICS_BY_NODE[nodeId]` 当对象数组取 `t.id / t.title`。
- **根因**：该结构实际是**题型 ID 字符串数组**（`["tp_factor","tp_poly"]`），需再查 `TOPIC_ITEMS` 取名称。
- **修法**：映射时用 `TOPIC_ITEMS.find(x => x.id === tid)` 补 `title`。
- **防线**：`TST-009` 题型关联字段填充断言。

### BUG-008: 页面引用了未定义的方法 / 字段

- **现象**：`node.js` 的 WXML 使用 `foldState` / `toggleFold`，但 JS 未定义；`graph.js` 动态 key `setData` 曾漏补。
- **根因**：先写 WXML 后补 JS，遗漏。
- **修法**：补齐 data 字段与方法定义。
- **防线**：`TST-002` JS 语法 + `TST-010` 模拟运行捕获运行时 undefined。

### BUG-009: o_geo_trans 例题只讲方法不给结论

- **现象**：题目问「正方形内点 P，PA=1,PB=2,PC=3，求 ∠APB」，解答只写"用旋转求出角度"，未给最终答案 135°。孩子看完仍不知道答案。
- **根因**：R1 编写讲解时按"讲思路"口吻写，遗漏结论落点。属于 `SPEC-008` 第一类内容缺陷。
- **修法**：补全旋转推导链（BP′=2、∠PBP′=90°、PP′=2√2、P′C=1，由 8+1=9 勾股逆定理得直角，45°+90°=135°），给出明确结论。
- **不可回退**：结论存在性属 `C3` 断言，任何"求 X"题必须给明确结论。
- **防线**：`TST-013`（结论存在性）+ `TST-015`（C4 一致性，断言 135° 存在）。

### BUG-010: s_vec3 二面角公式表述有误导

- **现象**：讲解写「用 cosθ=|n₁·n₂|/(|n₁||n₂|) 求出再判断」，把带绝对值的锐角余弦当作二面角余弦的通式。
- **根因**：绝对值只给出两法向量夹角的锐角值，二面角可能是其补角（钝角）；原表述易让孩子以为二面角恒为锐角。
- **修法**：改为"先算 |cos⟨n₁,n₂⟩| 得锐角参考值，二面角等于该角或其补角，结合图形定锐钝"，并显式点破不能把绝对值式直接当二面角余弦。
- **不可回退**：条件 / 范围的表述完整性受 `C2` 类断言约束。
- **防线**：`TST-015`（C4 一致性，断言锐钝说明存在）+ 人工闸门 `VFY-004`。

### BUG-011: 内容校验器自身浮点精确比较误报

- **现象**：`verify_content.js` 复算 s_vec 点积 `1×2×cos60°` 得 `1.0000000000000002`，与期望 `1` 精确相等判断失败，误报内容错误（实际内容正确）。
- **根因**：JS 浮点精度；校验器用了 `===` 精确比较。
- **修法**：改为容差比较 `Math.abs(a-b)<1e-9`（布尔/字符串仍用精确比较）。
- **不可回退**：校验器错误比不校验更危险（会产生假警报、损害信任）；所有数值断言必须容差比较。
- **防线**：`TST-013` 内容校验全绿（22/22）。
- **延伸教训**：UI 验证脚本的断言也连错三次（把"课程标准"全称写成"课标"缩写正则、把初中节点来源误设为竞赛大纲），每次都误报产品失败。根因同上——**测试断言的期望值本身是未经核实的假设**。故 `RUL-008` 人工闸门同样适用于校验脚本自身：断言失败时先判断"是被测对象错还是断言错"，不得直接改被测对象去迎合断言。

### BUG-012: 专题存疑切换按陈旧页面缓存取反（R35）

- **现象**：store已更新而专题页面points暂未刷新时，点击存疑可能保持最新值而不是切换；非法节点还会访问不存在的point。
- **根因**：toggleDisputed直接取points.find(...).disputed，未校验节点也未重读唯一store；与node页已采用的读取方式不一致。
- **修法**：先校验事件节点属于当前专题，再读取store.getDisputed(id)取反，setDisputed成功后才改页面；失败保留UI与业务状态。
- **防线**：TST-025在真实store/协议harness中覆盖两种陈旧值、非法事件/节点以及storage失败后重试；保留TST-024的真源审核与个人存疑分离断言。
- **执行状态**：已登记、待红绿回归，结果续记于TESTS。

> R35执行增补：已修复，真实记录回归46/46；主代理将取反点在内存替换成旧缓存读取，4项定向断言失败（42/46，预期exit1）。不改生产源码即可验证防线能抓住回退。证据见TST-025。
