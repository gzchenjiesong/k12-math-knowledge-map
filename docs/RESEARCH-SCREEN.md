# RESEARCH-SCREEN：多屏适配与投影可行性调研

> 状态：L1 横屏适配 + L2 演示模式已实现（2026-11-26，见 `tests/evidence/RESPONSIVE_V21.md`）；L3 大屏演示页待家长决定
> 调研日期：2026-11-26
> 触发：审核等待期，家长提出「iPad 横屏」与「讲解时投影到电视放大播放」需求
> 依据：微信开放文档（全局配置 / 响应显示区域变化 / 大屏适配指南 / VideoContext / WMPF 产品介绍），2026-11-26 核对

## 1. 结论速览

1. **iPad 横屏完全可行**，官方一等支持，改动集中在配置 + 样式断点，不动真源、不动数据契约。
2. **小程序不能主动把任意页面「投屏」到电视**：官方投屏 API 只绑定 `video` / `live-player` 组件，投的是视频流；本项目是静态卡片/图谱，此路不通。
3. **现实可行的电视路径有两条**：① 系统级屏幕镜像（AirPlay / Miracast）——零开发但依赖手机横屏先改好；② 大屏演示页投 URL——最贴合「投影放大播放」，但需新增一个生成式 HTML 交付物与可访问链接。
4. **当前项目零适配**：7 个页面全 `rpx`、全 `flex`、无一处 `@media`、未开 `resizable`。iPad 横屏下会等比放大导致「字巨大、内容稀疏」，必须先补断点。

## 2. 官方能力矩阵

| 能力 | 官方支持 | 关键配置 / API | 最低基础库 | 对本项目判定 |
|---|---|---|---|---|
| iPad 屏幕旋转 | ✅ | `app.json` 顶层 `"resizable": true` | 2.3.0 | **可行**；全局生效，iPad 上不能单页开关 |
| 手机屏幕旋转 | ✅ | `window.pageOrientation: "auto"` 或页面 json；`"landscape"` 固定横屏 | 2.4.0 / 2.5.0 | 可行，但按需开；横屏非主场景 |
| 响应尺寸变化 | ✅ | 页面 `onResize(res.size)` / `Component.pageLifetimes.resize` / `wx.onWindowResize` | 2.4.0 | 可做精细布局（如演示模式） |
| CSS 媒体查询 | ✅ | `@media (min-width: 480px) { ... }` | — | **核心手段**；当前项目零使用 |
| 声明式媒体查询 | ✅ | `<match-media>` 组件、`wx.createMediaQueryObserver` | — | 适合 WXML 层按宽度切布局 |
| 自适应栅格 | ✅ | `row` / `col` 组件（24 份，超出换行） | 扩展组件 | 可选；现有 flex 结构迁移成本中等 |
| PC 大屏模式 / 自由拉伸 | ✅ | `"resizable": true`（Windows / Mac / 车机 / 安卓 WMPF） | 2.21.3 | 附带收益，与 iPad 同一开关 |
| 微信小程序投屏到电视 | ❌ | `VideoContext.startCasting()` / `LivePlayerContext.startCasting()`，**仅视频组件** | — | **不适用**：本项目无视频内容 |
| 微信 TV 端原生运行时 | ❌ | 无面向家庭电视的「把已有小程序投上去」能力 | — | 不可行 |
| WMPF 硬件框架跑电视 | ⚠️ | 需终端合作平台注册、设备-应用-小程序绑定、逐台硬件注册 | — | B 端硬件接入流程，家庭场景不可行 |

## 3. 当前项目现状（2026-11-26 实测）

- `apps/miniprogram/app.json`：无 `resizable`、无 `pageOrientation`，窗口按手机竖屏锁定。
- 7 个页面 wxss：`rpx` 合计约 621 处、`px` 0 处、`@media` **0 处**、`grid` **0 处**、全 `flex` 布局。
- 后果：`rpx` 以 750 设计稿等比换算，屏幕越宽单个元素越大。iPad 横屏下不是「一屏看更多」，而是「放大版手机页」，内容稀疏、滚动冗长。
- 已有 HTML 交付物均为文档/打印形态（`.wrap{max-width:1180px}` 或 A3 固定 `420mm×295mm`），不是演示形态；其中 `deliverables/olympiad-knowledge-map.html` 标题仍为「初中→高中→奥赛」v1 老口径，若用于投屏需一并刷新。

## 4. 三条路径详述

### 路径 A：iPad 横屏适配（推荐先做）

- 开关：`app.json` 顶层加 `"resizable": true`。手机端不受影响；若也要手机横屏，再给指定页面 json 加 `"pageOrientation": "auto"`。
- 样式：关键页面加 `@media (min-width: 768px)` 断点，把单列改双列/三列（讲解页：左标题与导航、右正文；图谱页：领域卡两列；卡片页：网格）。
- 大字问题：断点内把 `rpx` 覆盖为 `px` 或百分比，避免等比放大。
- 精细控制：页面 `onResize` 得到 `windowWidth/windowHeight`，可加「演示模式」状态（隐藏 tabBar 视觉干扰、放大标题、聚焦当前知识点）。
- 工作量：低—中。纯前端，零破坏真源与数据契约。

### 路径 B：电视投影

| 方案 | 做法 | 优点 | 局限 | 判定 |
|---|---|---|---|---|
| B1 系统屏幕镜像 | iPad/手机开启 AirPlay / Miracast / 投屏 App 镜像，把整个微信画面投到电视 | 零开发；数据实时同步 | 手机需常亮；通知会弹；未适配时竖屏画面在电视上留黑边 | **低成本可用**，依赖路径 A 先完成 |
| B2 大屏演示页投 URL | 新增生成式 HTML（16:9、大字、单知识点聚焦/翻页），部署为链接，用电视浏览器或投屏工具「投网页」打开 | 最贴合「投影放大播放」；电视端独立显示，手机可操作其他事 | 需新交付物 + 托管；与小程序进度不同步 | **推荐作为进阶方案** |
| B3 小程序投屏 API | `VideoContext.startCasting()` | 官方原生 | 仅投 `video` 视频流；本项目无视频组件 | **不可行** |
| B4 WMPF 电视端运行 | 硬件接入微信终端合作平台 | 官方框架 | B 端设备注册流程，非家庭用户能力 | **不可行** |

### 路径 C：PC 大屏 / 分栏（附带收益）

同一个 `"resizable": true` 开关让 Windows/Mac 微信支持大屏窗口与自由拉伸；官方另有分栏模式可左右各显示一页。适合家长在电脑备课，优先级低于 A。

## 6. 风险与注意

- `resizable: true` 全局生效，iPad 上无法逐页关闭；开启后各页都必须至少「横屏不破版」，否则不能上线该开关。
- 只改布局不改内容，`pending=268`、`verified=0` 状态不变；机械校验全绿不代表人工签核。
- 当前 `1.0.0` 审核中：本地继续改代码不会改变已提交的审核版本；若本轮改动要随首版发布，需在审核通过后重新上传新版本（或等下一版本发布）。
- 后台账号介绍（含「授课卡片」旧文案）由家长在审批结束后人工修改，与代码包无关。

## 8. 小米生态补充调研（2026-11-26）

家长补充：手机与电视均为小米设备，电视自带「共享屏幕 / 投屏」。核对 Xiaomi HyperConnect 官方文档（`hyperos.mi.com/continuity/abilities/ab0011`）后，新增以下可行路径。

### 8.1 官方投屏能力与条件

| 方式 | 说明 | 条件 / 版本 |
|---|---|---|
| 屏幕镜像 | 下拉手机控制中心 → 投屏 → 选电视，整屏镜像 | 蓝牙 + WLAN 开启；手机与电视同一 Wi-Fi |
| 应用投屏 | 投屏时选「应用投屏模式」，只把当前应用投到电视，手机可另用 | **HyperOS 3+**（手机/平板/电脑端） |
| 投屏画中画 | 被投屏时电视端可切画中画，电视可同时做别的 | HyperOS 2+（手机/平板/电视） |
| 屏幕扩展 | 电脑窗口拖到电视作扩展屏 | 电脑端 HyperConnect |
| 小米电视「微信投屏」 | 电视端「无线投屏 → 微信投屏」扫码绑定后，微信内长按图片/音乐/**文档**分享到电视 | 不受同一 Wi-Fi 与距离限制；打开 PPT/Word/PDF 需电视端装 WPS |

电视侧协议：米联 / Miracast / AirPlay / DLNA（见小米电视规格页）。

### 8.2 对本项目的新增路径判定

| 路径 | 做法 | 判定 | 关键限制 |
|---|---|---|---|
| M1 系统屏幕镜像 | 手机开「投屏 → 屏幕镜像」，进入小程序讲解页 | **可行，零开发** | 已做的 L1/L2 横屏改造正好适配；手机需常亮、通知会弹 |
| M2 应用投屏 | HyperOS 3 选应用投屏模式投微信 | **条件可行** | 需确认微信是否在支持列表；仍需横屏适配 |
| M3 微信投屏分享文档 | 演示稿导出 PDF → 微信长按分享到已绑定的小米电视 → 电视 WPS 打开 | **可行且不依赖公网托管**（新增路径） | 静态，交互翻页靠遥控器；电视需装 WPS |
| M4 电视浏览器打开链接 | 演示稿部署公开 URL → 电视浏览器直接打开 | **体验最好** | 需公网托管；遥控器输入网址不便，宜短链或扫码 |

### 8.3 屏幕镜像黑屏风险

`FLAG_SECURE` 是 Android 窗口级标志，需宿主 App 主动设置才会阻止投屏/录屏捕获（银行、支付类常见）。微信一般页面不设此标志，本项目为静态图文卡片，无 DRM 视频内容，**镜像黑屏风险低**；但仍需在用户实际设备上验证一次。

### 8.4 待家长确认的硬件信息

1. 手机型号与系统版本（HyperOS 1/2/3 还是 MIUI）——决定 M2 应用投屏是否可用。
2. 电视型号与系统版本——决定画中画与微信投屏是否支持。
3. 电视是否已安装 WPS / 浏览器——决定 M3/M4 是否可直接用。
4. 是否接受把演示稿部署为公开链接——决定 M4 与 L3 最终形态。
