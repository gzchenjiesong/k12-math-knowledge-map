# deploy · 部署目录

## R35 当前说明（2026-11-27，优先于下方历史原文）

> **本目录不是当前小程序的直接部署入口。`deploy/server/` 是历史自建快照 API 样例，与当前微信云操作协议不兼容，不能只配置 `runtime-config.js` 就启用。**

- 当前内容由 `reliable-data/` 编译后内置，小程序记录经 `utils/store.js` / `utils/sync.js` 使用微信云开发。现行字段 Lamport 版本、稳定操作 ID、删除版本与旧记录只读迁移规则见 `docs/CONFIG.md` 的 CNF-022、`docs/RULES.md` 的 RUL-010；旧新客户端不得混写或直接回滚。
- 云端基础权限须为「仅创建者可读写」，当前实现不能直接切为自定义安全规则或开放读写。仓库 `apps/miniprogram/utils/cloud-config.js` **当前含非空 env，不是默认禁云**；首次 clone 应在编译/运行前把 env 设为空字符串、替换自己的小程序 AppID，以离线开始。启用自己的云环境前另行核实权限与升级要求，不使用仓库环境做测试。
- 每账号一份逻辑记录不等于一份固定大小云文档；当前操作日志随修改增长、拉取需分页扫描，没有自动压缩/删除历史，不能沿用“仅几 KB”的容量结论。限制及待验证成本见 CNF-022。
- 历史自建 API 只收发 `{ state, updatedAt }` 快照，不具备当前字段版本、删除与幂等操作语义；未来接入需单独设计适配与迁移并重新验收，不能宣称和当前 sync/store 完全一致。
- R33/R34 代表性隔离验收 PASS 不等于部署或全设备通过；VFY-007 的真实云权限、账号隔离、双设备真机与性能仍缺证，投屏后续实测 SKIPPED。最近回归与数量看 `docs/TESTS.md`，工程测试入口看 CNF-025：Node.js 18+、零依赖，无需 `npm install`，根目录 `npm test`。
- R35 是源码与文档整理，不执行部署脚本、改云权限或微信上传/提审/发布；GitHub 源码提交也不等于部署。下方“当前状态”“当前方案”和托管发布路径均为历史描述，不代表本轮核实的新审核或部署状态。

## 目录结构

```
deploy/
├── README.md               # 本文件
├── config/                 # 私有配置（不入库）：服务器地址、登录凭证、keys
│   └── .gitkeep
├── config.example.json     # 配置字段样例（占位值，可入库）
├── server/                 # 自建进度服务（零依赖 Node）
│   ├── server.js           # API + 鉴权
│   ├── lib/store.js        # 按用户隔离的进度存取
│   ├── config.example.json # 服务端配置样例（可入库）
│   ├── config.json         # 真实凭证（不入库）：AppID/Secret/token 密钥
│   ├── data/               # 用户进度文件（不入库）
│   └── README.md           # 服务端说明与微信前置条件
└── scripts/
    └── deploy-server.sh    # 上传/启动/健康检查（骨架，参数待填）
```

## 发布链路（已确认的架构）

- **内容**：可靠数据源内置到小程序包，离线可用，不经过服务器。
- **预览发布**：走 WorkBuddy 托管链路（应用卡 → 分享 → 试用/绑定），与后端无关。
- **进度同步（当前方案）**：小程序 `utils/sync.js` ↔ 微信云开发数据库 `progress` 集合，按 `_openid` 自动隔离，仅同步几 KB 的掌握状态/笔记/存疑标记。配置在 `apps/miniprogram/utils/cloud-config.js`，无需 AppSecret / HTTPS / 域名白名单。
- **自建服务器（备选）**：`deploy/server/` 保留自建进度服务，将来需走出微信生态时启用。详见 `deploy/server/README.md`。

## 安全红线

1. **`deploy/config/` 下的任何真实文件都不入库。** `.gitignore` 已用 `deploy/config/*` + 白名单例外排除。
2. **绝不把以下内容写进仓库**：服务器 IP/域名、SSH 私钥、API Key、token、数据库口令、云账号凭证。
3. 需要共享配置结构时，只提交 `*.example.json`（字段齐全、值为占位符如 `<YOUR_TOKEN>`）。
4. 私有信息文件只保留在部署机上，权限建议 `chmod 600`。
5. 若误提交过敏感信息：立即轮换凭证，再用 git 历史清理工具处理，不能只删当前文件。
